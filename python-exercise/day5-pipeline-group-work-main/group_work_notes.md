## Activity 1：设计城市报表流程

拒绝 t-004（`abc` 不是数字）、t-006（负车费）、t-008（空城市），共跳过 3 行。
城市先 `strip()` 去掉首尾空格，再 `title()` 统一大小写，因此 `Berlin`、`BERLIN`、`berlin`
归入 Berlin，` hamburg ` 与 Hamburg 归入 Hamburg。

| 步骤 / 函数 | 输入 | 输出 / 职责 |
| --- | --- | --- |
| Extract / `read_trips` | CSV 路径 | 用 `csv.DictReader` 读取，逐行调用验证函数；返回有效行程和跳过数 |
| Validate / `parse_trip` | 原始行字典 | 标准化城市并转换车费；无效行返回 `None`，有效行返回新字典 |
| Transform / `city_totals` | 有效行程列表 | 每个城市的总车费字典 |
| Transform / `format_report` | 总车费字典和跳过数 | 金额降序、同金额城市名升序的报表行，附总计和跳过数 |
| Load / `write_report` | 报告路径和报表行 | 用 `w` 模式替换报告，重复运行不重复追加 |

`make_sample_csv` 使用 `csv.DictWriter` 生成题目样例，仅在输入文件不存在时由 `main` 调用，
不会覆盖已有输入。函数均有 docstring。没有数据行时输出总价 0.00 和跳过数 0；
缺失城市或车费、非数字、非正数、NaN 和无穷大都会被跳过。

运行：

```bash

python3 broken_city_report.py
```

## Station 2：调试记录

开始本次检查时，数字转换异常、城市标准化和排序已经有相应处理，剩余明确问题是追加写入。
以下是四个调试检查点和可复现方法，不把已经修好的部分冒充本次新发现的错误；
原始未修改的教师版本未保存在当前目录，因此不推断它的准确行号。

| 症状 / 检查点 | 位置 | 验证方法 | 修复 / 当前处理 |
| --- | --- | --- | --- |
| `abc` 转数字会发生 `ValueError`，未经处理会中断脚本 | `parse_trip` | 在 REPL 执行 `float('abc')` | 用异常处理返回 `None`；补充缺失值与非有限数处理 |
| 同城市的空格和大小写导致分组分裂 | `parse_trip` | 对比 Berlin、BERLIN、` hamburg ` 的解析结果 | 已有 `strip().title()` |
| 金额顺序或同价顺序不符合题目 | `format_report` | 用不同金额以及同价城市验证排序 | 已有 `(-金额, 城市名)` 排序键 |
| 第二次运行后报告变成十行 | `main` 原写文件部分；现为 `write_report` | 连续运行两次，对比文件内容 | 将 `a` 改为 `w`，每次覆盖；加入重复运行回归测试 |

不要在真实数据目录随意删除 CSV；测试使用临时目录隔离输入输出。

## Station 3：评价同事代码

题目中的函数有以下问题（有些问题要先修复前面的错误才会暴露）：

| 问题 | 暴露问题的输入 / 操作 | 结果与改法 |
| --- | --- | --- |
| `totals={}` 是共享默认字典 | 在修复循环其他错误后，连续调用两次同一行数据 | 第二次累计上一次结果；在函数内部新建字典 |
| `.strip` 缺少括号 | `[{'city': ' Berlin ', 'fare': '1'}]` | 得到方法对象而非城市字符串；改为 `.strip()` |
| `.get(city)` 没有默认值 | 首次遇到任何城市 | `None + float` 触发 `TypeError`；改为 `.get(city, 0.0)` |
| 不统一大小写 | Berlin 与 BERLIN 各一行 | 被分成两组；先标准化城市 |
| 不验证空白城市 | `{'city': ' ', 'fare': '1'}` | 应跳过，不能计为空城市 |
| 不处理缺失键和 None | `{}` 或 `{'city': None, 'fare': None}` | `KeyError` 或 `AttributeError`；在验证步骤检查字段 |
| 不处理非数字车费 | `{'city': 'Berlin', 'fare': 'abc'}` | `ValueError`；转换失败返回无效标记 |
| 不拒绝非正数和非有限数 | 车费为 `-4`、`0`、`nan`、`inf` | 负数影响总价，NaN/无穷大污染整个结果；检查正数及有限性 |
| 不统一最终小数位 | 同一城市的车费为 `0.1`、`0.2` | 浮点误差；汇总返回时取两位，展示时用 `.2f` |

空输入：题目函数返回共享字典，可能带着上次的结果。坏行：可能直接报错。
同一程序重复运行：修复其他错误后仍会因共享默认值重复累计。
最难察觉的风险是状态跨调用共享：程序可能不报错，却让金额越来越大。
当前实现把验证和汇总分开，每次 `city_totals` 都创建独立字典。
